RottenDouban v6.1 - 烂番茄豆瓣聚合评分
==========================================

一句话：聚合烂番茄 + 豆瓣评分的静态站，数据由 GitHub Actions 定时抓取，本地什么都不用装。
线上地址 https://lxj070514.github.io/rottendouban/

核心功能:
- 烂番茄新鲜度 + 爆米花指数
- 豆瓣评分 + 评分人数
- 加权评分（影评人 0.3 + 观众 0.3 + 豆瓣 0.4，缺失源按比例重分配权重）
- 运行时零第三方依赖，只用 Python 标准库
- 暗色/亮色主题、响应式、搜索与筛选

数据源:
- 烂番茄: Algolia 搜索 API
- 豆瓣:  搜索页内联的 window.__DATA__（带缓存 douban_cache.json）
- TMDB:  可选，配了密钥才补海报/简介/编剧

匹配原则（重要）:
  标题规范化后必须完全相同 + 年份必须吻合（±1），对不上就放弃该源。
  RT 索引里有大量同名翻拍片和重映活动，宽松匹配会把 2018 年的同名片
  当成 1997 年的泰坦尼克号。宁可少显示一个分数，不能显示错的。
  因此《七宗罪》《你的名字》《活着》等 RT 索引里确实没有的片子不显示番茄分。

部署链路:
  crawl-deploy.yml  周一/周四 04:00 UTC：抓取 → 校验 → 提交数据 → 部署
  deploy-site.yml   push 改了前端时只部署，不重新抓取
  ci.yml            跑离线测试
  抓取与部署拆成两个 job：environment 若挂在抓取 job 上，一失败就会留下
  永久 queued 的 Pages deployment，把后续所有 run 堵死（历史数据停更的成因）。

本地开发:
  python -m pytest              离线测试，不需要网络
  python -m crawler.main        完整抓取（会发豆瓣/RT 请求）
  CRAWLER_LIMIT=5 python -m crawler.main   只跑前 5 部，调试用
  cd site && python -m http.server 8080    预览

环境变量:
  CRAWLER_MODE             full / douban_only / site_only
  TMDB_API_KEY             可选
  MIN_MOVIES_TO_PUBLISH    发布下限，默认 50，抓太少就不覆盖线上数据
  CRAWLER_INSECURE_SSL     设 1 跳过证书校验，仅本地代理排障用
